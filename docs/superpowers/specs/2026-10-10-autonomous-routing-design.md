# 自主会话、模型路由与双入口派工 v0.7

本版由 2026-10-10 用户明确授权实施，覆盖 v0.6 的固定 Astra 模型和默认两个待命子实例规则。机器 A/B/C 的群权限、主从优先级、板卡边界不变。

## 设计

采用任务路由器、持久会话目录和共享派工账本；不修改全局供应商或 ChatGPT 凭据。相比只改提示词，此方案能在程序边界校验路由、任务去重和恢复；相比替换 Codex，保留原生 GPT 子代理与现有 DeepSeek 控制通道。

每个独立 task_id 自动建立一个持久 GPT 主会话；同任务跟进复用该会话，重启后 thread/resume 恢复。主模型、effort 只从本机 model/list 的可用选项中选择。明确简单回复可用轻量模型，复杂度不明或关键决策、验收、困难问题、关键优化、评估一律使用质量主模型及其最高可用档位。自主 route 工具可安排当前会话下一回合和新会话的模型/档位；正在生成的回合不可更换解码模型。主会话工具创建的新任务进入持久收件箱，不在当前回合递归运行。

所有 GPT 主会话共享本机现有 Astra 飞书机器人，DeepSeek 执行实例共享现有 DeepSeek 机器人。只有主会话接收群指令；子代理必须由主会话授权发布结果。不同模型不产生新飞书身份。

启动不预建任何数量的子实例，不读取旧 default_children 设置。DeepSeek 工作在派工时自动分配或扩展，任务结束可回收，模型/provider/effort 固定 deepseek-flash/deepseek/max。数量由任务需求决定，程序不设置业务数量上限。物理资源、供应商限制和 Codex 原生并发限制仍有效。

同一个 task_id + task_version + work_id 在 DeepSeek 与原生 GPT 入口共享唯一派工记录。相同请求返回原 job_id，冲突输入拒绝。各工作声明文件所有权；重叠工作拒绝并行。原生 GPT 仅在专门能力需求下使用：先 reserve 获得租约，子代理 validate，完成后 complete；未领取有效租约的原生子代理不得执行项目工作。不得自动对不确定的外部副作用进行第二次派工。进程异常后未终结的工作标 interrupted，明确人工/主会话决定后才重试。

子代理用于在不影响质量的前提下减少 GPT usage 和分担执行压力；主模型保留决策、验收、重难点、关键优化、评估。不能以低质量子代理结论替代主模型验收，不能声明未经测量的 usage 节省比例。

修复结构化错误通知与 willRetry；仅目标线程/回合的终态决定成功或失败。常驻服务采用登录计划任务、单实例进程锁、自动故障重启、实时健康端点；空闲状态不调用模型。普通项目聊天通过项目 MCP 或稳定 CLI 接入同一目录和账本。

## 验收

单元及集成验收包括独立任务分会话、跟进复用、重启恢复、模型及 effort 可用范围、关键工作质量保护、跨入口重派去重、文件冲突、取消/过期任务、Flash/max 请求守卫、原生租约检查、重试通知恢复、常驻单实例。

真实请求核对主回合 model/effort/session，DeepSeek 请求/服务端回包和持久结果；原生 GPT 子代理验证租约并返回结果。常驻服务启用后从 CLI 运行任务、读回健康、强制故障恢复、核对群身份不变化。群身份以实际应用与原有群历史只读核对；不改变 B/C 或操作实体板卡。Windows 执行环境与服务监督器以实际故障注入修正，监督器负责重启、独占锁和进程树收尾，不调用模型。
