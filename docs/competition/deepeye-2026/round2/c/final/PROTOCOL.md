# C 协议候选 C-FINAL-1

这是C单机方案的可实现ABI，取代本目录范围内旧稿“待A冻结”的建议；不擅自改变三机公共ABI。实现开始前以新实施版本锁定。以下是规范/算术，尚无编解码或线测通过声明。

## 帧与编码

300 baud、8N1、半双工共享容量；4秒计量窗。UART接收/发送方向逻辑互斥，物理可以有两根信号线，任何时刻只放行一个方向，不计双向各300的容量。连接设备必须实测支持300 baud。

头尾总16B：magic2=`A5 5A`、version1=`01`、type1、total_length1、session_epoch2、seq2、board_tick_ms4、flags1、CRC2。所有多字节整数小端。CRC16/CCITT-FALSE：poly=0x1021、init=0xFFFF、refin/refout=false、xorout=0；从magic至最后负载均覆盖，CRC值小端附后，`123456789`参考值0x29B1。总长16–32B，完整候选CRC通过才交业务；坏长度跳1字节重搜，CRC失败继续有界32B滑窗，不能把噪声magic当有效帧。连续20ms字节间隙不足一个300baud字符，不用它判帧结束；帧按长度解析，接收超时取最大帧串行时长加100ms。

|type|总长|负载/语义|
|---|---|---|
|0x01 SUMMARY|≤32B|RAW为四均值、四极差，各u16共16B；均值用整数舍入向下；有效范围0–4095。tick为窗口结束；flags低4位是各通道有效，高4位依次GAP、任一饱和、Rice、保留0|
|0x02 COMMAND|24B|action u8、target u16、lease_ms u16、risk_generation u16、reserved u8=0；seq为命令ID，tick引用完整已收摘要的板时刻|
|0x03 STATUS|24B|command_seq u16、phase u8、output_readback u16、fault u8、config_epoch u16；phase=0无命令/1accepted/2applied/3rejected。反馈只报告当前阶段，不保证每个中间阶段均单独发帧|
|0x04 EVENT|16B|无负载；seq为风险代次，flags风险位；重复同一锁存风险不增加代次；tick为触发时刻|
|0x10/0x11/0x12 SESSION|24B|仅停止状态启动/应答/确认：8B随机挑战；epoch与挑战联合建立会话；会话帧也计线字节|

摘要Rice负载：k u8（0–16）、第一个u16绝对值、随后7个差分的Rice位流，按统计量表中顺序，字节内MSB先发、末字节0填充。差分先以至少17位有符号计算，映射 d≥0为2d，否则为-2d-1；商q为q个0后跟1，余数k位。预测重建以前一实际值为基准。只有整个负载≤15B才选Rice，否则发16B RAW，禁止为追求“压缩率”扩大最大帧。序列预估若超过RAW成本即终止，不生成无界unary。空窗/采样不足需valid/GAP，不伪造均值。完整收到摘要可逐位还原统计量，不等于全量曲线无损。长原始块用于PS档案/离线算法试验，不隐含在线大帧。

STATUS的output_readback来自板端输出引脚回环采样，表示实际PWM量化占空比（0–10000，0xFFFF无效），不是命令目标，也不是RP2040独立捕获值。实际布线不具备板端回环时填无效并报故障，不能用寄存器值冒充回读。RP2040独立采集PWM、RUN/FAULT和输出命令序号，其USB高速链只用于显示/审计。此区分修复第二轮未说清“谁采集输出”的问题。

COMMAND固定 action=0 STOP、1 HOLD、2 SET_VIRTUAL_HEADING、3 ENABLE；target为0–10000映射虚拟偏转范围，非真实角度测量。lease上限12000ms，开始于首次applied，重复同一ID仅重发状态、不重施加不续期。相同ID不同内容拒绝。未建立会话、观测年龄>12000ms、risk代次不匹配、参数越界均拒绝。风险STOP本地锁存；ENABLE还需本地风险消退及新鲜完整有效摘要。会话合法STOP优先应用，但仍须CRC/长度正确。

seq16比较仅接受前进差值1–32767，最多保留一个未确认命令；跨回绕先停输出并重新建立会话。tick32用模差值，任何可接受跨度远小于2^31ms。epoch16重启须改变；重启/重新握手时双方停业务、清解析/命令缓存、丢弃旧队列，至少静默最大旧帧时间后执行挑战应答。不允许带旧业务帧跨会话持久重传。回绕或epoch无法可靠更新时停输出；CRC/epoch不是安全认证机制，本方案不主张抗恶意注入。

config_epoch核心固定1，v1不支持动态profile，删除旧稿需要额外分片配置但没有定义完整协议的隐患。新profile后续单独版本化并重算预算。phase不使用completed，避免持续PWM动作何时“完成”的歧义。输出到期进入HOLD/STOP，故障工况记录，不延迟等待PC确认。

## 调度与容量

4秒×300/10=120线字节等价容量。常规最大 SUMMARY32 + COMMAND24 + STATUS24 =80B；累计换向guard0.2s，2.8667s占71.67%。加EVENT16为96B，3.4s占85%；余18B等价容量，容得下一次16B事件重传，装不下24B命令重传。重传用后续命令槽替换新命令，不能偷偷加一个ACK。

每窗至少保留一个下行命令槽和一个上行状态槽，常规三类按SUMMARY→COMMAND→STATUS顺序；事件在完整帧边界优先插入，每窗最多首发一次和重传一次。PC收到SUMMARY/EVENT后，在约定guard开始发送COMMAND或保活HOLD；板端只在下行槽等待，不与PC争发。事件不抢走保留命令/状态槽，超额同代风险合并、不同风险累加flags，PS保存完整事件；摘要过期只保最新并记GAP。候选队列上限：摘要1、事件合并记录1、待命令1、状态最新1；档案独立计溢出，不阻塞本地保护。

启动SESSION最少3×24B，至少2.4s串行加guard，单列启动阶段；不把它藏在稳态85%内。风险风暴/重握手/丢帧下不承诺正常时延。正常最大不可抢占阻塞32/30=1.0667s，8秒P99/12秒max仍须S4/S6验证；12秒TTL/新鲜度为本C候选值，若实际排队不满足，必须改版本或降低负载，不偷偷放宽验收。

没有转义开销，CRC只用于误码检测；解析必须做坏magic、坏长度、跨帧拼接、重复、回绕、丢字节/插字节向量。限速、guard和全部实际字节由逻辑分析仪/端口采集验证，模拟时间不能写成真实线测。
