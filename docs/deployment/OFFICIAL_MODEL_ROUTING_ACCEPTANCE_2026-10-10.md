## 可点击的模型更新

双击仓库内 `deploy/更新官方模型.cmd`，再点击页面“更新官方模型”。入口从常驻服务发现当前地址，服务重启后无需手改端口。已通过实际浏览器点击确认更新成功并显示十二个入口；Desktop MCP 的 `fpga_models_refresh` 也通过真实调用，服务器版本为 `0.8.0`、工具十五项。

更新启动当前已安装 Codex Desktop 捆绑的 app-server，读取完整、分页的官方 `model/list` 及支持的推理深度，重新生成全局原生角色和项目允许目录。未来命名不要求固定 `gpt-` 前缀；官方新模型自动得到入口。真实目录当前十个条目、七个可见模型；目录和权限以更新时结果为准。质量主模型仅按已列出的官方升级指示迁移，关键任务仍必须最高档位。

更新没有推理调用，也不改写账号凭据。空目录、请求失败、用户自定义角色同名冲突或写文件失败会保留旧配置；文件替换失败已测试回滚。刷新与正在读取的旧目录共用锁，旧响应不能覆盖新目录。页面仅监听本机环回地址，更新需要同源页面令牌。新角色定义在新加载的会话生效；正在生成的回合按原路由结束。新模型须已由 OpenAI 向该账号及客户端开放，按钮不安装客户端，也不能取得未开放的模型权限。目录规则参见 [官方 app-server 文档](https://learn.chatgpt.com/docs/app-server)。

## 双入口、主从与常驻

- 指定 API key 路径保持不变；DeepSeek 真实执行 `sum(range(1,101))` 并写文件，结果 5050。终结结果的 provider/model/effort 为 `deepseek` / `deepseek-flash` / `max`。
- 十个原生任务再次经 DeepSeek 入口提交，全部复用原 job、没有分配子实例；DeepSeek 已完成任务经原生入口提交也复用原 job。跨入口活动写路径冲突拒绝执行；取消预留任务后释放路径。
- 子代理无默认、最低或规定数量。此次按需执行后回收为 0，重启仍为 0；v0.7 的三实例并行及扩缩实测继续有效。原生入口仅供主模型说明特殊能力需要后调用，执行前须验证绑定的父级租约。
- 同一主线程真实完成 Luna/low → Astra/ultra 两回合，provider 均为 `openai`。决策、验收、重难点、关键优化和评估仍由质量主模型完成；本轮审查与验收由主模型执行，子代理只承担有边界的计算和文件执行。
- A 机 Astra、DeepSeek 应用的非秘密 ID 与机器人 ID 经线上只读核对，与原身份一致；本轮没有为验收发送群消息。全部主会话共用 Astra-A，全部 DeepSeek 共用 DeepSeek-A。
- `FPGA-Mesh-Node-A` 常驻任务已注册并运行；飞书连接成功、`feishu_error` 和 `quota_error` 为空。修复停止后立即重启的租约竞争，并在项目外工作目录实跑注册/重启。服务恢复后十个原生任务、一个 DeepSeek 任务和原主线程均保留。运行 PID 与当前页面地址是时间敏感数据，查实时健康接口。
