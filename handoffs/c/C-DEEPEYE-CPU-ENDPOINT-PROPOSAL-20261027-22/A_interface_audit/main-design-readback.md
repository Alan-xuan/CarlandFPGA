## Bytes and correlation

Private frame header is exactly 16 bytes, struct `>4sBBHII`: magic `C22E`, version 1, kind, reserved flags 0, metadata length, payload length. Input kinds OBSERVE=1, END=2; output RESULT=129, ENDED=130. No ready banner, error frame, or other stdout bytes. Input metadata and output metadata each have an independent 2048-byte cap. Input TOTAL header+metadata+payload <=16384 bytes, as required by A's existing InvocationTranscript raw-write cap. Original record payload independently <=16384 but must also fit that total; raw payload capacity is therefore smaller when wrapped. Output original encoded payload <=4096 bytes INCLUDING its original LF; response TOTAL <=6160 bytes (=16+2048+4096), within A's separate 8192 ActorPolicy cap. Future A raw read budget must include all response framing, not only encoded payload.

Input metadata has EXACT keys `identity`, `frame_index`, `payload_sha256`. Identity has EXACT original A keys `operation_id`, `request_hash`, `tested_commit`, `package_manifest_sha256`, `run_id`, `invocation_id`, `actor_instance_id`. Validate labels and digest/integer bounds to match the exact current A source at PR24 5c192f34bad064b14e238747c2c569347257a62c; duplicate keys, nonfinite constants, malformed UTF8, extra/missing keys, bool-as-int and invalid types are errors. No A module import. JSON encoders use ASCII, sorted keys, compact separators, no NaN; parser need not impose JSON serialization order. Request payload hash is the complete SHA256 of unchanged raw payload. END payload is empty with SHA256 of empty bytes.

Response metadata has EXACT keys `identity`, `frame_index`, `request_frame_sha256`, `request_payload_sha256`, `payload_sha256`. Identity and frame_index echo the parsed immutable current request; request_frame_sha256 hashes EVERY original input frame byte, including original metadata serialization/header; request_payload_sha256 hashes original record bytes; payload_sha256 hashes unchanged original core encoded bytes (including LF). A's `identity.request_hash` is the operation correlation hash; it is NOT request_raw_sha256. Future A prepared transcript request_raw_sha256 must equal request_frame_sha256 if it writes this full frame. No self-hash is embedded in the input. No hash or identity label establishes authentication, package provenance, availability, completion, clock or motion permission.

## Lifetime and I/O

No prefetch: CLI uses exact-size `os.read` against fd0 and one original `os.write` against fd1 per whole response frame. On Windows set binary mode on fd0/fd1. Do NOT use buffered stdin/stdout or A's inactive multi-frame decoder. Read only the current header, current metadata and current payload, handling partial positive reads by advancing exactly the returned bytes. EOF, None, nonbytes, oversize reads or exception retire with no further reads/writes. Never consume a future header before current response's exact successful write. A future owner must dispatch one input and read its complete correlated response before another input.

One response emission is ONE write call; exact returned count == frame length required. Short count, zero, None, bool, invalid count or exception means unknown/partial completion and immediate retirement, no remainder write, no retry, no second error frame. CLI stderr may receive one bounded ASCII diagnostic code; never payloads, credential values or unbounded traceback. No background thread, process spawning, service, clock, handle adoption or runtime writer. Pure driver functions may accept bounded read/write callables for controls; production CLI always raw OS I/O. No public fake-core mode or factory injection argument; controls privately replace the internal constructor.

Frame_index starts at 1, advances exactly by one, max65536 inclusive. At most65535 OBSERVE frames so one final END fits. Invocation_id strictly increases; other six identity fields remain exactly frozen from the first OBSERVE. END requires an active stream and next identity/index. END outputs the unchanged core EndReceipt then returns immediately without reading tail bytes. Input EOF even at a frame boundary without END is abnormal retirement, not a completion acknowledgement. First frame must be OBSERVE. Limit total accepted input wire bytes <=64MiB and total emitted output wire bytes <=64MiB; check before core observation / any write respectively. No reactivation, reconnect, session rollover or retry after any error. Expose only lower-bound caps for small pure tests if useful; never CLI bypass switches.

Construct exactly one fixed FrozenForceStream lazily only after first frame syntax/hash/identity validation. Before import/constructor, verify actual sibling stream_core.py bytes SHA256 0a8c07f34080784f36180951b28873b43de5e3f80ad201325254b274bd01217b. Use original C21 fixed manifest and CPU settings unchanged, with StreamLimits(max_output_bytes=4096) (all other default caps unchanged). Start once with generation=1, epoch=0 and a deterministic local run_id derived from frozen identity hash (e.g. `c22-` + SHA256 of canonical identity with invocation_id omitted), <=128 UTF8 bytes. Local generation/epoch/token never accepted from wire or promoted to A authority. Observe forwards the exact record bytes; use only `.encoded`, preserve every byte. A core exception retires the entire endpoint even though the core itself might remain active. END calls end_session once. On EOF/error after successful start, cleanup attempts local end_session at most once; discard cleanup receipt and never write it. No failed constructor/start/observe/end/write is retried. CLI exit0 only after successful END reply; all abnormal retirement exit nonzero. Cleanup failure makes exit nonzero and produces no extra stdout. Borrowed test streams are not closed/adopted; normal process exit closes only the CLI's own ordinary stdio.
