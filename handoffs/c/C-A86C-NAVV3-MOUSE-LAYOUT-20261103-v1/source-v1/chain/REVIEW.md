## Two retained source defects and one withdrawn allegation

### C55-F1: late broker issue does not revalidate the complete requested duration

Relevant current source: `simulation/authority/owned_invocation_v1/adapter.py:261–270,276–296`; `g05_csr_channels_v1.py:584–620`; `actor_composition.py:124–163`; `integration/completion_interval.py:133–152`; `pc_direct_runtime.py:412–441,478–506`.

The adapter validates interval/caps and calls `adapt_action_candidate` at result admission, retaining a finite candidate with that issue time. `_completion` checks the retained finite deadline before offering the one-use proof; after consumption it clears the retained tuple. A later `broker_next` waits for the original mailbox window, parses the pending proof, copies its target unchanged, and writes a **new** `host_issue_monotonic_ns=now`. It validates the envelope shape, but does not repeat the full-duration interval adapter check at that new issue time. The progress gate verifies interval order and `now < candidate.valid_until_ns`, not `new_issue + duration <= original caps`.

Concrete static counterexample definition: relative to a common genuine QPC origin, initial validation/issue at 1.0s, original candidate validity cap 4.2s, positive target duration 3000ms. The first finite action ends at 4.0s and fits. A genuine later slot at 1.3s is still before the old finite deadline and the original cap, but the copied target now requests through 4.3s. The existing `adapt_action_candidate` would refuse that new issue; `broker_next` does not invoke it. This is a source-derived proposed vector, **not an executed result**.

Impact is precise: the broker can emit a full-duration request that its original interval contract would reject. This review does **not** claim motion beyond the original source/AI deadline. Runtime command validity takes a minimum with source age, and `_ready` independently fences each STEP against command/health/AI limits; it can stop before the advertised target duration. Silent shortening/inconsistent promised duration is the defect, not demonstrated over-cap movement.

Minimal A-owned change: at the actual broker issue, retain/recover the original validated interval and exact source/dispatch/previous caps from its original proof, rerun the existing full-duration adapter, and refuse a target that no longer fits. Do not replace caps with arrival time, advance source origin, reduce duration silently, or change legacy envelope semantics. Make any attempted/refused slot's retry/retirement policy explicit in the original owner rather than replaying a side effect.

### C55-F2: historical mutable candidate bytes are not rechecked before projection

Relevant current source: `simulation/authority/g05_csr_projection_v1.py:40–79,135–157,167–171,192–203`; `_Mapping` in `g05_csr_channels_v1.py` and the same file's current-observation admission.

The current mapping has `_raw(m.candidate)==m.retained_bytes` at lines167–171. Each historical selected mapping is subsequently passed to `_public_observation`, which calls `_original_mapping` and reads `mapping.candidate['channel_counts']`, quality, times, and capture ID. `_original_mapping` verifies genuine retained source/token/preparation/phase and re-correlates the original E4 wire/CRC. It does **not** compare the historical candidate's serialized bytes with its own retained snapshot, nor use the freshly verified returned frame values to reconstruct the public values it emits.

Trigger: while all genuine retained refs, event, original wire, phase and current mapping remain unchanged, an in-process mutation of a **historical** mapping's candidate to a different otherwise legal nonsaturated EM count is selected by the rolling window. Its original E4 re-correlation still succeeds; the emitted history contains the changed candidate value. The new EM3 core uses such native history for map costs, so this is relevant to planning, not merely display. No product mutation or counterexample was executed here.

Scope is deliberately narrow: this is an original retained mutable-object revalidation gap. It does not establish an external caller bypass of genuine owner/Root/type checks, and it does not make CRC ineffective on the actual wire. The source and board provenance checks remain present; a separately retained derived value is the unchecked part.

Minimal A-owned change: before projecting **each selected historical/current** mapping, compare its candidate canonical bytes with its original retained snapshot, and keep its raw observation/source-time/count association consistent with the reverified frames. Reject before child dispatch on change. Do not fabricate replacement provenance, admit plain JSON, or discard the original journals to avoid the check.

### C54-F3 remains withdrawn for this installed upstream path

`source_projection_v1/source_poll.py` computes the first 10ms grid point at/after the actual completed transition using integer ceiling. `tools/run_causal_functional_chain.py:345–368` routes `FunctionalSource.poll_sample` through `poll_after_finished_transition` when a transition exists; that checks the original latest completed transition and attachment before source polling. `tools/diagnostic/causal_pl_exchange.py:281–341` derives the actual current 10ms bin and, under NavV3, accepts it only when `tick % 1000 == 0`.

Nav therefore accepts the first 10ms bin of a second when reached, skips other bins, and does not floor a late sample back to an earlier 1s origin or backfill missed samples. For a completion just after a second boundary, the ceil-10ms guard prevents using that earlier nominal bin; the next eligible Nav sample is later. The projector's lack of a standalone repeated span check is not proof of a natural timing bypass through the installed original producer. The upstream compensating gate is retained in e470; no F3 runtime failure is claimed.
